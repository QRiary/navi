# How NAVI is built

NAVI is a desktop app: **Electron** (main process, files, QMK CLI, flashing) + a **React** interface (Vite, TypeScript, zustand).
The interface talks to the main process only through `window.navi` (`electron/preload.cjs` ⇄ `src/desktop/bridge.ts`).
Everything that does not touch the screen or the disk lives in `src/core` as plain, tested functions.

```
electron/        main process: window, app:// protocol, IPC, projects on disk, QMK CLI, flashing
src/core/        pure logic (no React, no DOM): keycodes, project model, QMK generator, VIA protocol
src/store/       zustand stores: project (+ undo/redo, draft), device, QMK jobs, settings, toasts
src/pages/       one file per section (Keyboard, Layers, Encoders, …)
src/components/  UI pieces used by the pages
src/styles/      CSS (tokens, layout, effects, keyboard)
scripts/         data generator from QMK sources, dev launcher, icon renderer
build/           app icon (icon.svg is the source)
```

## Key ideas

- **Geometry is separate from assignments.** A keymap stores keycodes by firmware matrix position (row × col) — the same
  way VIA and QMK store them. The geometry (where keys physically are) only points to matrix positions, so you can
  move keys, add geometry variants or import a layout without touching the keymap.
- **Layers are numbers in QMK.** Reordering or deleting layers goes through `src/core/project/ops.ts`, which renumbers
  `MO()/LT()/TG()…` and the references inside tap dance and combos.
- **Nothing is faked.** Connection, write, build and flash statuses come only from facts: the keyboard's answer,
  reading back after a write, the exit code, a device appearing. Unknown hardware stays “unknown”; guesses are marked
  with evidence `heuristic`.
- **Every project change is undoable:** `useProjectStore.apply(fn, label)`.

## Build safety

Building runs `make` on the user's computer, so a project file must not be able to run programs:

- `rules.mk` may only contain variables from an allowlist (`…_ENABLE`, `…_DRIVER`, `…_TYPE`, `SRC` with `.c` files).
  `CC`, `SHELL`, `CFLAGS` and the like would run a program and are rejected.
- Own code from an imported project is not written to files until the user has read it and pressed “allow”
  (`firmware.customReview`).
- The main process checks the files again right before writing (`electron/safety.cjs`).
- QMK files are written only into the keymap folder (or a new target) and only after showing a diff;
  the previous files go to `%APPDATA%\NAVI\backups\qmk`.
- Before a build, every file in the keymap folder and `users/<keymap>` must pass the same allowlist (`.mk` → make
  check, other text → C include check; links, files too big to read and over 5000 files fail), or the build is
  refused, unless the user trusted that folder (`electron/trust.cjs`). Trust is kept only in
  `<userData>/trusted-folders.json` (never in a project or import/export, never set by a file in the folder), is
  granted only through a warning dialog shown by the main process, and can be revoked. NAVI's own generated files
  still go through the allowlist either way.

## Project format

A project is a JSON document (`format: "navi.project"`, `schemaVersion`). A new field means
`PROJECT_SCHEMA_VERSION + 1`, a migration in `src/core/project/migrate.ts` and a test.
